# 图片渐进式加载优化 — 产品需求文档 (PRD)

> 状态：设计通过 | 日期：2026-05-09 | 版本：v1.0
> 关联技术文档：`2026-05-09-image-optimization-tech-spec.md`

## 📋 摘要（给人看）

**问题**：首屏图片加载时显示黑色空白，然后突然弹出，用户感知体验差。

**方案**：实现 Medium/Unsplash 式的 Blur-up（模糊渐显）——先用 CDN 80px 缩略图模糊显示，主图加载完成后平滑过渡到清晰。改动完全局限在 `OptimizedImage` 一个组件内部，40+ 处引用自动受益，零破坏性。

**目标**：首屏图片可见时间从"黑色 → 突然出现"变为"模糊 → 清晰"的持续可见状态；代码结构清晰可维护；不引入新依赖。

**成功标准**：

- 所有已有图片正确显示，无布局偏移（CLS < 0.1）
- 首屏图片从"空白"变为"有模糊占位"的时间 < 200ms
- 主图加载完成后 400ms 内完成平滑过渡
- TypeScript 类型检查通过，ESLint 无报错
- 40+ 处引用零改动正常运行

## 1. 背景与动机

### 1.1 业务背景

项目基于 Next.js 15 App Router，使用统一图片组件 `OptimizedImage`（`libs/ui/src/components/OptimizedImage.tsx`）覆盖全站 40+ 处图片渲染场景。CDN 已支持 6 档尺寸（80/100/150/350/600/800）。

### 1.2 用户痛点

- **首屏空白焦虑**：页面打开后图片区域显示为黑色或透明空白，用户不知道图片是否在加载
- **突然出现**：图片加载完成后瞬间弹出，缺乏过渡，视觉体验生硬
- **对比竞品**：主流平台（Medium、Pinterest、Unsplash、Amazon、Shopify）均有平滑的图片加载过渡

### 1.3 上次失败的教训

之前尝试修改图片组件导致：

- 部分图片完全不显示
- 部分图片高度被限制为 80px

根因分析：缺乏充分测试矩阵、组件状态管理不清晰、布局约束未正确传递。

## 3. 功能需求

### 3.1 Blur-up 加载流程

```
图片请求开始
  │
  ├─ [blurSrc 存在] → 立即渲染 80px 缩略图 + blur(20px) + scale(1.1)
  │                   容器显示为模糊色块（非黑色空白）
  │
  ├─ [blurSrc 不存在] → 直接渲染主图 + opacity: 0
  │
  ▼
主图 onLoad 触发
  │
  ├─ 缩略图 opacity: 1 → 0（300ms）
  └─ 主图 opacity: 0 → 1（400ms）
```

### 3.2 组件状态机

```
         ┌──────────────────────────────────┐
         │                                  │
         ▼                                  │
     ┌───────┐   src 变化   ┌──────────┐   │
     │ idle  │ ───────────→ │ loading  │   │
     └───────┘              └──────────┘   │
                                │    │     │
                    onLoad ┌────┘    └─────┘
                           │         onError
                           ▼              ▼
                     ┌────────┐    ┌──────────┐
                     │ loaded │    │  error   │
                     └────────┘    └──────────┘
```

### 3.3 触发条件

**启用 blur-up**：

- CDN 图片（URL 路径可被 `detectPathInfo()` 识别）
- Strapi 图片对象（有 `formats.thumbnail`）
- 非 SVG 格式

**跳过 blur-up（回退到纯 fade-in）**：

- 本地静态图（`/images/`、`/_next/`）
- 外部非 CDN URL（如 Unsplash 直链）
- SVG 格式
- `disableBlurUp={true}` 显式禁用

**直接跳过（保持现有行为）**：

- 无 src
- 加载出错

## 4. 非功能需求

### 4.1 性能

- `blurSrc` 必须是纯计算（同步），不引入额外异步请求到 JS bundle
- 缩略图下载本身是浏览器行为（`<img>` 标签），与主图并发，不阻塞渲染
- 不引入新的 npm 依赖
- SSR 可正确计算 `blurSrc`（无水合不匹配）

### 4.2 代码质量

- `OptimizedImage` 组件职责拆分：状态管理逻辑与渲染逻辑分离
- 新增代码必须有 TypeScript 类型
- 遵循项目文件架构规范（`libs/ui/` 为 L0 原子组件层）

### 4.3 兼容性

- `OptimizedImageProps` 接口**不能变化**（移除、改名、必选变可选等）
- 只能新增可选 prop，不能修改已有 prop 语义
- 必须兼容所有现有使用场景

## 6. 风险与回滚

| 风险                        | 影响                         | 缓解措施                                   |
| --------------------------- | ---------------------------- | ------------------------------------------ |
| 缩略图 URL 错误导致加载失败 | 显示降级为当前行为           | `onError` 静默回退                         |
| 布局偏移（CLS）             | 用户体验下降                 | 缩略图绝对定位在容器内，不改变容器尺寸     |
| 与现有组件动画冲突          | ProductImageGallery 切换异常 | 不修改现有动画逻辑，Blur-up 只作用于加载态 |
| 性能回退                    | LCP 增加                     | 缩略图不额外增加阻塞请求                   |

**回滚方案**：所有改动限 `OptimizedImage.tsx` 一个文件，可通过 `disableBlurUp` prop 全局关闭，或直接 git revert。

## 7. 范围边界

### 包含

- `OptimizedImage` 组件的 blur-up 改造
- `resolveBlurSrc()` 缩略图 URL 生成逻辑
- loading → loaded → error 状态机
- CSS 过渡动画

### 不包含

- 后端 Strapi 改动（缩略图生成等）
- Next.js `images` 配置修改
- 其他组件的改动
- 图片压缩/格式优化（已有 AVIF/WebP）
- 预加载策略调整（已有 `priority` 逻辑）
- LQIP base64 内联生成
