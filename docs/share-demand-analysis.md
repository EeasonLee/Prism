# Share 功能需求分析

## 背景

当前 Prism 的分享功能已经具备基础能力，但仍偏向“功能存在即可”的一期实现：能分享，但还没有真正围绕电商成交场景去设计。对于厨房电器这类客单价相对更高、决策周期更长、常伴随家庭讨论的商品，分享不应只是一个社媒出口，而应被理解为辅助成交的沟通工具。

这意味着分享模块的目标，不是让用户把商品“发到更多平台”，而是让用户更顺手地把商品“发给会影响购买决策的人”。

## 北美厨房电器购物场景

在北美电商环境下，厨房电器通常不是纯冲动型购买。用户在浏览商品详情页时，往往会经历以下几类真实场景：

- 和伴侣确认是否购买，尤其是价格较高或占空间的厨房电器
- 发给家人或朋友征求意见，确认品牌、容量、尺寸或性价比
- 在搬家、婚礼、节日送礼等语境下，把商品发给相关人讨论
- 在移动端看到商品后，转发到聊天工具，稍后再在桌面端继续决策

因此，这类分享更接近“私下转发”和“共同决策”，而不是公开发布动态。

## 用户分享心理

对这类商品，用户点击分享按钮时，通常不是为了表达态度，而是为了完成一个明确任务：

- 让别人帮自己判断
- 把商品留到另一个聊天场景继续看
- 发送给具体的人推动购买决策
- 在礼物、家庭采购、小家电升级等语境中快速同步信息

从这个心理出发，分享功能最重要的不是“平台覆盖广”，而是“动作阻力低”。

一个好的分享模块应该让用户在很短时间内完成以下动作：

1. 复制链接
2. 发给某个人
3. 明确知道自己已经分享成功

## 渠道判断

如果从真实使用场景出发，分享渠道应优先支持高频、低摩擦、面向具体联系人的路径，而不是堆一排传统社媒图标。

更符合当前北美电商场景的优先级通常可以分成两层：

核心动作：

- `Copy link`：最通用，适合发到任意聊天工具、群聊、备忘录或稍后使用
- `SMS / iMessage`：非常接近日常沟通路径，特别适合移动端快速转发
- `Email`：适合送礼、工作场景、跨设备留存或更正式的转发
- `WhatsApp`：适合部分国际用户、家庭群、小群讨论和跨文化沟通场景

补充社媒：

- `Facebook`
- `X`
- `Pinterest`

这类平台型入口更偏“公开发布”或“社交内容传播”，对厨房电器 PDP 的实际成交帮助通常不是第一优先，但它们可以在第一版中作为补充出口存在，用来满足用户认知预期和完整度感受。

因此，当前阶段更合理的做法不是完全排斥社媒 icon，而是建立清晰层级：先把最真实的成交路径做强，再把传统社媒作为次级补充，并为后续基于点击数据做删减留出空间。

## 对当前 Prism 方案的判断

当前实现的问题，不在于技术不可用，而在于产品定位还停留在“基础分享组件”层面：

- 渠道选择过于轻量，缺少更贴近真实转发场景的动作设计
- 复制链接缺少明确反馈，不利于建立操作确定感
- 桌面端和移动端的 UI 都更像基础菜单，而不是成交辅助工具
- 整体信息架构仍偏“我提供几个分享动作”，而不是“我帮助你把商品发出去”

所以当前版本可以视为一期基础能力，但还不能算真正达到上线标准。

## 产品结论

Prism 的分享模块，下一阶段不应按“社媒按钮组件”继续演进，而应按“转化型分享工具”来定义。

这意味着后续设计原则应明确为：

- 以 `Copy link` 作为最强主操作
- 优先支持私域转发，而不是公开社媒分发
- 移动端优先顺应原生分享习惯，桌面端强化快速复制和低阻力操作
- 让用户对“是否已经分享成功”有明确感知
- 在视觉上保持次级，不抢购买主流程，但在功能上必须足够顺手

一句话总结：

> 对 Prism 来说，分享功能的价值不是“增加几个社媒图标”，而是降低用户把商品发给决策相关人的阻力，从而提高讨论、回流和成交机会。
